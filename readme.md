# Stack Lisp VM

Учебный проект на Python: компилятор Lisp-подобного языка в собственный ассемблер и бинарное представление для стековой архитектуры.

Проект охватывает несколько уровней — от лексического и синтаксического анализа исходного кода до генерации инструкций собственной ISA и прототипа виртуальной машины.

## Как устроен проект

```text
Lisp source (.lsp)
       │
       ▼
     Lexer
       │
       ▼
     Parser
       │
       ▼
      AST
       │
       ▼
 CodeGenerator
   │       │
   ▼       ▼
 ASM      binary
             │
             ▼
      Stack VM prototype
```

Основные этапы компиляции реализованы отдельно:

- `Lexer` разбирает исходный текст на токены;
- `Parser` строит AST;
- `CodeGenerator` преобразует AST в инструкции собственной архитектуры;
- генератор умеет формировать как читаемый ассемблер, так и бинарное представление команд;
- исполнительная часть разделена на `ALU`, `DataPath` и `ControlUnit`.

## Возможности языка

Генератор кода поддерживает:

- целые числа, строки и булевы значения;
- переменные и присваивание;
- арифметические операции;
- логические операции;
- сравнения;
- условные конструкции;
- циклы `for`;
- функции и вызовы функций;
- ввод и вывод.

Пример программы:

```lisp
(function process-maths ()
    (print "a is negative")
)

(process-maths)
```

Примеры исходных программ находятся в `progs/`.

## Компиляция

Проект не требует сторонних Python-зависимостей.

Клонирование:

```bash
git clone https://github.com/andrey8080/stack-lisp-vm.git
cd stack-lisp-vm
```

### Lisp → ASM

```bash
python3 main.py -asm progs/file2.lsp progs/asm/file2.asm
```

Проход компиляции:

```text
source → tokens → AST → assembler
```

### Lisp → binary

```bash
python3 main.py -bin progs/file2.lsp progs/bin/file2.bin
```

В этом режиме исходная программа проходит те же этапы, после чего инструкции кодируются в бинарный формат собственной ISA.

> Текущий CLI реализует генерацию `asm` и `binary`. Исполнительная часть VM присутствует в виде отдельных компонентов и прототипа `machine.py`, но пока не подключена как завершённая команда запуска из `main.py`.

## Архитектура виртуальной машины

Стековая модель включает:

- **Program Memory** — память команд;
- **Data Stack** — стек операндов;
- **Call Stack** — стек вызовов;
- **ALU** — выполнение арифметических и логических операций;
- **DataPath** — состояние данных и взаимодействие компонентов;
- **Control Unit** — управление выполнением инструкций.

Основные регистры архитектуры:

| Регистр | Назначение |
|---|---|
| `SP` | указатель вершины стека |
| `PC` | адрес следующей инструкции |
| `IR` | текущая инструкция |
| `SR` | флаги состояния `NZVC` |

## Формат инструкций

В текущем генераторе бинарная инструкция состоит из:

```text
8-bit opcode + 12-bit operand/address
```

Для безадресных инструкций поле операнда заполняется нулями.

Примеры:

```text
PUSH 05A
LOAD 003
JMP L1
ADD
```

Для числовых значений используется 11-битное представление; отрицательные числа кодируются в дополнительном коде.

## Набор команд

| Инструкция | Назначение |
|---|---|
| `PUSH` | положить значение в стек |
| `POP` | удалить верхнее значение |
| `ADD`, `SUB`, `MUL`, `DIV` | арифметические операции |
| `AND`, `OR`, `NOT` | логические операции |
| `LOAD`, `STORE` | чтение и запись памяти |
| `IN`, `OUT` | ввод и вывод |
| `CMP` | сравнение значений |
| `JMP` | безусловный переход |
| `JZ`, `JNZ` | переход в зависимости от нулевого значения |
| `JLT`, `JLE`, `JGT`, `JGE` | переходы по результату сравнения |
| `JEQ`, `JNE` | переходы по равенству / неравенству |
| `CALL`, `RET` | вызов функции и возврат |

Полный список opcode определён в `isa.py`.
